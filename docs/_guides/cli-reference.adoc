= CLI Reference

Complete reference for the Etassia command-line interface.

== Getting Help

Running `etassia` without a command displays the command list. The root help
forms below do the same:

[source,shell]
----
etassia
etassia help
etassia -h
etassia --help
----

Use `help` with a command name for that command's usage and options:

[source,shell]
----
etassia help render
etassia help batch
----

The CLI also provides a command tree:

[source,shell]
----
etassia tree
----

`--help` and `-h` are root-level help forms, not command options. For example,
`etassia render --help` treats `--help` as the input file and fails if that file
does not exist. Use `etassia help render` instead.

== Commands

=== render

Render one diagram as SVG.

[source,shell]
----
etassia render [FILE]
----

==== Argument

`FILE`::
  Optional diagram input file. When omitted, or when `FILE` is `-`, Etassia
  reads source from standard input. For a file, Etassia tries its registered
  extension before inspecting the source to select a notation.

==== Options

`--output PATH`, `-o PATH`::
  Write SVG to `PATH`. Without this option, SVG is written to standard output.

`--format FORMAT`, `-f FORMAT`::
  Output format. Defaults to `svg`; SVG is the only supported format.

`--theme THEME`, `-t THEME`::
  A built-in theme identifier or a path to a theme YAML file. Built-in themes
  are `default`, `dark`, `light`, and `high_contrast`.

`--verbose`, `-v`::
  Enable verbose output. It defaults to false. On an error, verbose mode also
  prints the backtrace.

`--notation NOTATION`::
  Use the named registered notation instead of detecting one from the file
  extension and then the source.

`--require PATH`, `-r PATH`::
  Load a notation file before rendering. This option is repeatable. Each file
  must register its notation with Etassia.

==== Examples

Render a file to an SVG file:

[source,shell]
----
etassia render diagram.mmd -o diagram.svg
----

Render standard input, with either supported stdin form:

[source,shell]
----
cat diagram.mmd | etassia render
cat diagram.mmd | etassia render -
----

Select SVG explicitly and use a built-in theme:

[source,shell]
----
etassia render diagram.mmd -f svg -t dark -o diagram.svg
etassia render diagram.mmd -t high_contrast -o diagram.svg
----

Select a notation explicitly, or load one supplied by another file:

[source,shell]
----
etassia render --notation mermaid diagram.txt
etassia render --require ./my_notation.rb diagram.my
----

=== batch

Render diagram files in a directory.

[source,shell]
----
etassia batch [OPTIONS]
----

`batch` has no positional argument; use `--input` or `-i` to choose input.

==== Options

`--input PATH`, `-i PATH`::
  Input directory or file. Defaults to the current directory (`.`).

`--output PATH`, `-o PATH`::
  Output directory. Defaults to `output`.

`--theme THEME`, `-t THEME`::
  A built-in theme identifier or a path to a theme YAML file. There is no
  explicit option default.

`--verbose`, `-v`::
  Enable verbose output. It defaults to false.

`--notation NOTATION`::
  Restrict directory discovery and rendering to the named registered
  notation. Without this option, all registered notation extensions are
  included.

`--require PATH`, `-r PATH`::
  Load a notation file before discovering inputs. This option is repeatable.

When the input is a directory, Etassia recursively finds regular files whose
case-insensitive extensions belong to the selected notation, or to any
registered notation when `--notation` is omitted. It writes an `.svg` file
under the output directory with the same relative path. Discovery excludes
dotfiles and does not descend into hidden subdirectories of the selected input
directory.

For example:

[source,shell]
----
etassia batch -i diagrams -o output
etassia batch -i diagrams -o output -t dark
etassia batch -i diagrams -o output --notation mermaid
etassia batch -i diagrams -o output -r ./my_notation.rb
----

Batch status is reported in its summary. Current edge-case behavior is:

* A nonexistent input path finds zero files, prints
  `No diagram files found in: PATH`, and exits 0 -- this counts as success
  (nothing failed), the same as an input directory with no registered diagram
  files in it.
* A direct file input renders that one file into the output directory even if
  its extension is not registered. A registered extension is replaced by
  `.svg`; an unregistered extension is retained.
* A file that fails to render does not stop later files. The summary
  records successes and failures, and the command exits 1 if any file
  failed, 0 if every file succeeded (including a run that found none).

=== types

List the diagram types registered by the current executable:

[source,shell]
----
etassia types [OPTIONS]
----

Output begins with `Supported diagram types:`. It then groups identifiers under
each registered notation. The built-in registration is:

----
mermaid:
  flowchart
  sequence
  class_diagram
  state_diagram
  er_diagram
  user_journey
  pie
  gantt
  timeline
  quadrant
  git_graph
  mindmap
  kanban
  radar
  block
  requirement
  xychart
  architecture
  sankey
  packet
  treemap
  c4
  info
  error
----

==== Options

`--require PATH`, `-r PATH`::
  Load a notation file before listing. This option is repeatable. Each
  additional notation is printed as another group.

=== version

Show the Etassia version:

[source,shell]
----
etassia version
etassia --version
etassia -V
----

Each form prints:

----
etassia version 0.1.0
----

== Environment Variables

The CLI does not currently read any `ETASSIA_*` environment variables.

== Exit Behavior

Successful commands and root help exit 0. Errors handled by `render`, such as a
missing input file or an unsupported format, print `Error: ...` and exit 1.

`batch` records individual render failures in its summary instead of aborting,
then exits 1 if any file failed and 0 if every file succeeded -- a missing
input path or empty input directory counts as 0 files succeeding, 0 failing,
so it exits 0 rather than 1.
